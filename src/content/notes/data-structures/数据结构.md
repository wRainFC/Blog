# 第一章 绪论

> [!quote]+ 程序设计的核心
>
> **程序 = 数据结构 + 算法**
>
> 这一公式由瑞士计算机科学家 Niklaus Wirth 提出，说明程序设计需要同时考虑数据的组织方式和处理数据的方法。

数据结构课程主要研究两类内容：

- **基本数据结构**
  - 线性结构：线性表、栈、队列、数组、串、广义表
  - 非线性结构：树、图
- **基本数据处理技术**：搜索与排序

## 1.1 数据结构的概念

早期的计算机主要用于数值计算，运算对象通常是简单的整型、实型或布尔型数据。随着计算机应用扩展到非数值计算，程序需要处理结构更复杂的数据，而且数据元素之间的关系往往无法用数学方程直接描述。

> [!example]- 问题与数据结构的对应关系
>
> 这类问题通常使用表、树、图等结构建立模型。例如：
>
> - 学生信息表可以表示为线性表；
> - 四皇后问题的求解过程可以表示为状态树；
> - 课程之间的先修关系可以表示为有向图；
> - 城市之间的煤气管道及其铺设代价可以表示为带权图。

因此，数据结构研究程序中的操作对象，以及这些对象之间的关系和可执行的操作。

### 基本术语

- **数据**：信息的载体，是描述客观事物的数、字符以及其他能够输入计算机并由程序识别和处理的符号的集合。
- **数据元素（数据成员）**：数据的基本单位。在不同问题中，也可以称为元素、结点、顶点或记录。
- **数据对象**：具有相同性质的数据元素的集合。例如，整数数据对象或学生数据对象。

### 定义 数据结构

$$
Data\_Structure=\{D,R\}
$$

其中，$D$ 是某一数据对象，$R$ 是该对象中所有数据成员之间关系的有限集合。

### 数据结构的三个方面

1. **逻辑结构**：从用户和问题的角度描述数据元素之间的逻辑关系，独立于计算机的具体实现。
2. **物理结构（存储结构）**：逻辑结构在计算机中的表示和实现，依赖具体的存储方式。
3. **操作及其实现**：定义在数据结构上的插入、删除、查找等操作，以及这些操作的具体算法。

例如，学生表的逻辑结构是线性表，可以使用数组或链表存储，并支持插入、删除和查找等操作。

> [!important] 逻辑结构与存储结构
>
> 算法的设计取决于选定的逻辑结构，算法的最终实现则依赖采用的存储结构。

### 存储结构中的映像

存储结构是逻辑结构在存储器中的映像：

- **数据元素的映像**：任何数据元素在计算机中最终都表示为二进制位串。
- **关系的映像**：数据元素之间的逻辑关系最终表示为存储位置关系或指针链接信息。

### 关系的映像方法

对于关系对 $\langle x,y\rangle$，常见的映像方法有以下四种：

1. **顺序映像（顺序存储）**：用数据元素之间的相对存储位置表示逻辑上的后继关系。例如，$y$ 的存储位置与 $x$ 的存储位置相差一个固定常量 $C$。这种存储结构只保存数据元素本身，位置关系隐含了元素之间的关系。
2. **链式映像（链接存储）**：在数据元素之外增加指针，用与 $x$ 一起保存的指针指出 $y$ 的存储位置。
3. **索引存储**：建立附加的索引表，通过索引项记录关键字和数据元素存储地址之间的对应关系。
4. **散列存储**：根据数据元素的关键字计算其存储地址，使关键字与存储位置建立直接联系。

### 数据结构的分类

- **线性结构**：元素之间通常具有一对一的前驱、后继关系，如线性表、栈和队列。
- **非线性结构**
  - 层次结构：元素之间具有一对多关系，如树、二叉树和堆。
  - 网状结构：元素之间可以具有多对多关系，如图。
  - 群结构：元素同属一个集合，但集合内部不强调固定的先后或层次关系。

## 1.2 数据结构的抽象形式

### 定义 数据类型

一组性质相同的值的集合，以及定义在这个值集合上的一组操作的总称。

> [!note]+ 类型决定值域与操作
>
> 不同类型的变量所能取的值的范围不同，所能进行的操作也不同。
>
> 例如，16 位整型 `int` 的取值范围可以表示为 $-32768\sim32767$，可执行的基本算术操作包括 $+、-、*、/、\%$。

### ADT：抽象数据类型

抽象数据类型（Abstract Data Type，ADT）由用户定义，用于表示应用问题中的数据模型。它由数据对象和定义在这些对象上的一组操作组成。

> [!important]+ 如何理解 ADT 中的“抽象”
>
> “抽象”是指提取能够反映问题本质的内容，同时忽略非本质的实现细节。ADT 将逻辑设计与物理实现分离，并支持封装和信息隐藏。
>
> ADT 可以从两种视图理解：
>
> - **设计者视图**：根据问题定义 ADT 包含的数据，给出相关操作的实现，并提供公共接口。
> - **用户视图**：只通过公共接口使用 ADT，不需要了解其内部存储和具体实现。对用户而言，ADT 可以看作一个黑盒。

> [!example]- 自然数 ADT 示例
>
> 设自然数对象集合是从 $0$ 到机器可表示的最大整数 $MaxInt$ 的有序子集，可以定义以下操作：
>
> - `Zero()`：返回自然数 $0$。
> - `IsZero(x)`：若 $x=0$，返回 `True`，否则返回 `False`。
> - `Add(x, y)`：若 $x+y\le MaxInt$，返回 $x+y$，否则返回 $MaxInt$。
> - `Subtract(x, y)`：若 $x<y$，返回 $0$，否则返回 $x-y$。
> - `Equal(x, y)`：判断 $x$ 与 $y$ 是否相等。
> - `Successor(x)`：若 $x=MaxInt$，返回 $x$，否则返回 $x+1$。

## 1.3 作为 ADT 的 C++ 类

面向对象方法可以概括为对象、类、继承和对象间通信。C++ 中的类能够同时描述数据及其相关操作，因此可以直接体现抽象数据类型的思想：

- 数据成员保存对象的状态；
- 成员函数实现 ADT 中规定的操作；
- `public` 成员构成面向用户的公共接口；
- 非公共成员隐藏存储方式和实现细节。

使用 C++ 描述面向对象程序时，还需要掌握数据声明、作用域、对象、输入输出、函数与参数传递、函数名和运算符重载、动态存储分配、友元函数、内联函数，以及结构和联合等内容。

## 1.4 算法定义

算法是为计算机处理问题而编制的一组指令，是解决问题的策略。数据结构表示问题的数学模型，算法描述如何在该模型上完成处理。

### 算法的描述方法

常见的算法描述方式包括：

- **自然语言**：用日常语言逐步说明算法。
- **流程图**：用特定图形符号表示算法流程。
- **伪语言**：结合程序设计语言的基本控制结构和自然语言描述算法。
- **类语言**：使用接近高级程序设计语言的形式描述算法，如类 C 语言。

### 算法的五个特性

- **有输入**：有 0 个或多个输入。
- **有输出**：有一个或多个输出，即处理结果。
- **确定性**：每一步的定义都确切且无歧义。
- **有穷性**：执行有限步后必须结束。
- **有效性**：每一步运算都足够基本，能够实际执行。

> [!example]- 选择排序示例
>
> 选择排序每一趟在尚未排好序的区间中找到最大元素，并把它放到该区间的末尾：
>
> ```cpp
> void selectSort(int a[], const int n) {
>  for (int i = n - 1; i > 0; --i) {
>      int maxPos = MaxKey(a, 0, i);
>      if (maxPos != i) {
>          std::swap(a[maxPos], a[i]);
>      }
>  }
> }
> ```

## 1.5 算法性能分析与度量

### 算法的性能标准

- 正确性
- 可使用性
- 可读性
- 效率
- 健壮性
- 简单性

算法的效率包括时间代价和空间代价。时间代价指算法的执行时间，空间代价指算法执行过程中所需的最大存储空间，两者都与问题规模有关。

### 算法效率的衡量方法

- **后期测试**：在算法的某些位置插入计时函数，测量完成某项功能所用的时间。测试结果会受到 CPU、存储系统和运行环境等因素影响。
- **事前估计**：在实际运行前，通过分析算法所执行的基本操作和占用的存储空间来估计算法复杂度。

### 时间复杂度

程序的总时间可以分为编译时间和运行时间。分析算法时，通常重点考察运行时间。

**程序步**是语法或语义上有意义的一段指令。

> [!example]+ 程序步的计算约定
>
> - 注释：程序步数为 0；
> - 声明语句：程序步数为 0；
> - 表达式、赋值语句：程序步数为 1；
> - 循环语句：循环控制语句每执行一次，程序步数为 1。

> [!example]- 用 `count` 统计程序步
>
> 以迭代求数组元素之和为例，在程序中插入 `count` 语句，记录原程序各部分的执行次数：
>
> ```cpp
> long long count = 0;
>
> float sum(float a[], const int n) {
>  float s = 0.0;
>  count++;                 // s = 0.0
>
>  for (int i = 0; i < n; i++) {
>      count += 2;          // 循环控制
>      s += a[i];
>      count++;             // s += a[i]
>  }
>
>  count += 2;              // 循环结束时的控制操作
>  count++;                 // return
>  return s;
> }
> ```
>
> 循环体执行 $n$ 次，每次计 $3$ 步；循环外共计 $4$ 步，因此
>
> $$
> count=1+3n+2+1=3n+4.
> $$
>
> 一个语句本身的程序步数，不一定等于执行该语句所需的总程序步数。例如，赋值语句 `x = sum(R, n);` 本身需要 1 个程序步。如果函数 `sum(R, n)` 的程序步数为 $3n+4$，这条赋值语句一次执行的总程序步数就是 $3n+5$。

> [!warning] 辅助计数语句不属于原算法
>
> 插入的 `count` 语句只用于记录原程序步数，不计入被分析算法本身。

> [!important] 为什么采用渐近分析
>
> 准确统计程序步数通常十分困难，而且程序步数本身也不能精确反映实际运行时间。因此，算法分析更关注运行时间随问题规模增长的趋势。

#### 算法的渐近分析

算法的运行时间通常会随问题规模增长。设问题规模为正整数 $n$，统计算法中的关键操作，并把关键操作重复执行的次数作为算法的时间度量。

> [!tip]+ 从循环估算时间规模
>
> 若关键操作的执行次数是 $T(n)$，则：
>
> - 常量语句的关键操作执行次数为 $1$；
> - 单层循环执行约 $n$ 次，时间规模为 $n$；
> - 两层各执行 $n$ 次的嵌套循环，时间规模为 $n^2$。
>
> 由于精确计算 $T(n)$ 往往较困难，通常用渐近时间复杂度估计算法执行时间的数量级。

#### 渐近时间复杂度

**大 $O$ 表示法**：当且仅当存在正整数 $c$ 和 $n_0$，使得对所有 $n\ge n_0$ 都有

$$
T(n)\le c\cdot f(n),
$$

则称算法的时间增长率属于 $O(f(n))$，记为

$$
T(n)=O(f(n)).
$$

例如：

$$
T(n)=2.7n^3+3.8n^2+5.3=O(n^3).
$$

使用大 $O$ 记号表示的时间复杂度称为算法的渐近时间复杂度（Asymptotic Complexity）。

> [!summary]+ 常见复杂度的增长顺序
>
> $$
> O(1)<O(\log_2 n)<O(n)<O(n\log_2 n)<O(n^2)<O(n^3)<O(2^n)<O(3^n)<O(n!).
> $$

#### 大 $O$ 表示法的运算规则

> [!summary]+ 大 $O$ 表示法的运算规则
>
> 如果 $T_1(n)=O(f(n))$，$T_2(m)=O(g(m))$，则：
>
> - **加法规则**，适用于顺序执行的并列程序段：
>
>   $$
>   T(n,m)=T_1(n)+T_2(m)=O(\max(f(n),g(m))).
>   $$
>
> - **乘法规则**，适用于多层嵌套循环：
>
>   $$
>   T(n,m)=T_1(n)\times T_2(m)=O(f(n)\times g(m)).
>   $$
>
> - **忽略常数因子**：
>
>   $$
>   T(n)=O(c\times f(n))=O(f(n)),\qquad O(c)=O(1).
>   $$

例如，一个程序先用两层循环处理 $m\times n$ 个元素，再用一个长度为 $m$ 的循环输出结果，其时间复杂度为

$$
O(\max(mn,m))=O(mn).
$$

起泡排序在最坏情况下需要进行数量级为 $n^2$ 的比较和交换，因此其渐近时间复杂度为 $O(n^2)$。

### 渐近空间复杂度

空间复杂度描述算法执行过程中所需的最大存储空间随问题规模变化的趋势。设算法的空间复杂度函数为 $S(n)$，若它与 $f(n)$ 具有相同的渐近增长数量级，则记为

$$
S(n)=O(f(n)).
$$

当问题规模 $n$ 足够大时，$S(n)$ 反映算法所需存储空间如何随 $n$ 增长。例如：

- 只使用若干个与问题规模无关的变量，空间复杂度为 $O(1)$；
- 使用长度为 $n$ 的辅助数组，空间复杂度为 $O(n)$；
- 使用规模为 $n\times n$ 的辅助矩阵，空间复杂度为 $O(n^2)$。
