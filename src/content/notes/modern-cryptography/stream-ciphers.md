## 一、流密码与伪随机生成器

### 1. 基本思想

流密码（stream cipher）是一个确定性算法：输入短随机种子，持续输出看起来随机的比特流。它常用于：

- 生成伪随机比特流，作为 PRG 的实现；
- 通过密钥流与明文 XOR 来加密任意长度消息。

优点是效率高、硬件实现简单、可处理任意长度消息；缺点是流密码本身通常只是算法设计，不能自动提供严格的安全证明，必须单独分析其输出是否具有足够伪随机性。

### 流密码的形式化定义

流密码由两个确定性算法组成：

1. **初始化**：

$$
st_0:=\mathrm{Init}(s,[\mathrm{IV}]),
$$

输入种子 $s$ 和可选初始化向量 IV，输出初始状态 $st_0$；

2. **取出比特**：

$$
(y_i,st_i):=\mathrm{GetBits}(st_{i-1}),\quad i=1,2,\ldots
$$

其中 $y_1,y_2,\ldots$ 是密钥流（keystream），$st_i$ 是更新后的状态。实际系统中一次输出的 $y_i$ 往往是一个字节或一个比特块，而不是单个比特。

### 用流密码实例化 PRG

给定流密码和期望输出长度 $l$，可定义：

1. $st_0:=\mathrm{Init}(s,\mathrm{IV})$；
2. 对 $i=1,\ldots,l$，计算 $(y_i,st_i):=\mathrm{GetBits}(st_{i-1})$；
3. 输出 $y_1\Vert\cdots\Vert y_l$。

如果流密码输出对 PPT 区分器看起来像均匀随机，则该算法就能作为 PRG 使用。

这里的 IV 通常不是秘密，它的作用是让同一个长期密钥在不同消息上产生不同的初始状态；安全要求是同一密钥下 IV/nonce 不重复，且接收方能够获得它。

## 二、用流密码加密

### 基础加密

生成与明文等长的密钥流 $Y$，然后 XOR：

$$
C=M\oplus Y,\qquad M=C\oplus Y.
$$

它具有高效、简单、无需填充等优点，但只提供机密性。攻击者翻转密文中的某一位，会使解密后的明文对应位也翻转，因此实际系统还需要消息完整性/认证机制。

若攻击者把 $C$ 改成 $C'=C\oplus\Delta$，接收方解密得到

$$
M'=C'\oplus Y=M\oplus\Delta.
$$

这就是流密码的可控位翻转攻击；没有认证标签时，接收方无法判断修改发生过。

### 密钥流不能复用

若两条消息使用相同的密钥流 $Y$：

$$
C_1=M_1\oplus Y,\qquad C_2=M_2\oplus Y,
$$

则

$$
C_1\oplus C_2=M_1\oplus M_2.
$$

攻击者可以利用已知明文、语言规律或两条明文之间的关系恢复信息。因此每次加密都必须使用新的 IV/nonce，并确保不会生成相同的密钥流。

### 两种工作模式

- **同步模式（synchronized mode）**：收发双方状态同步；若丢失一个比特，后续状态可能全部错位。
- **非同步模式（unsynchronized mode）**：系统可从密文重新建立同步，但通常要付出额外开销。

同步模式的密钥流只依赖初始状态和时钟，传输错误不会自动恢复；非同步模式让后续状态依赖部分已接收的密文，丢失少量数据后可能重新同步，但错误可能在一段窗口内传播。

## 三、线性反馈移位寄存器

### LFSR 的形式化定义

一个 $n$ 阶 LFSR 包含：

- $n$ 个 1 比特寄存器 $s_{n-1},\ldots,s_0$；
- $n$ 个反馈系数 $c_{n-1},\ldots,c_0$；
- 当前状态为全部寄存器中的比特。

每一步更新为：

$$
s_i^{(t+1)}=s_{i+1}^{(t)},\quad i=0,\ldots,n-2,
$$

$$
s_{n-1}^{(t+1)}=\bigoplus_{i=0}^{n-1}c_i s_i^{(t)}.
$$

输出序列为 $s_0^{(0)},s_0^{(1)},s_0^{(2)},\ldots$。

### 2. 四阶例子

取反馈系数 $(c_3,c_2,c_1,c_0)=(0,1,0,1)$，初始状态 $(0,0,1,1)$。状态依次为：

```text
(0,0,1,1) -> (1,0,0,1) -> (1,1,0,0) -> (1,1,1,0)
             -> (1,1,1,1) -> (0,1,1,1) -> (0,0,1,1) -> ...
```

输出比特为：

```text
1, 1, 0, 0, 1, 1, 1, 1, ...
```

### 3. LFSR 的周期性与不安全性

状态只有 $2^n$ 种，因此状态序列最多经过 $2^n$ 步就必然重复；选择合适的反馈多项式并从非零状态出发时，最大周期可以达到 $2^n-1$。四阶 LFSR 的状态空间只有 16 个状态，上面的序列很快重复。即使精心选择反馈系数，使 LFSR 遍历全部非零状态，它仍不适合密码学：内部更新是线性的，观察少量输出即可重建整个状态和反馈关系。

### 4. 重建攻击

对一个 $n$ 阶 LFSR，观察连续 $2n$ 个输出比特后，通常可以解出：

- 初始状态的 $n$ 个比特；
- 反馈系数的 $n$ 个比特。

四阶例子中，观察到 8 个输出 `1,1,0,0,1,1,1,1`。前四个输出可确定初始状态 $(0,0,1,1)$，后四个输出给出关于 $(c_3,c_2,c_1,c_0)$ 的四个 GF(2) 线性方程：

$$
\begin{aligned}
1&=c_3\cdot0\oplus c_2\cdot0\oplus c_1\cdot1\oplus c_0\cdot1,\\
1&=c_3\cdot1\oplus c_2\cdot0\oplus c_1\cdot0\oplus c_0\cdot1,\\
1&=c_3\cdot1\oplus c_2\cdot1\oplus c_1\cdot0\oplus c_0\cdot0,\\
1&=c_3\cdot1\oplus c_2\cdot1\oplus c_1\cdot1\oplus c_0\cdot0.
\end{aligned}
$$

解得 $(c_3,c_2,c_1,c_0)=(0,1,0,1)$。从此攻击者可以预测全部后续输出。

## 四、加入非线性：RC4

### 1. 非线性的作用

为阻止 LFSR 的线性重建攻击，可在以下位置引入非线性：

1. 状态更新过程；
2. 从状态生成输出的过程；
3. 两者同时加入。

RC4、Trivium 等流密码都采用了不同形式的非线性设计。

### 2. RC4 概况

RC4（Rivest Cipher 4，也称 ARC4/ARCFOUR）由 Ron Rivest 于 1987 年设计，软件和硬件实现都很高效，曾用于 WEP、TLS/SSL 等。但后续研究发现了严重的统计偏差和实际攻击，RC4 已不应继续用于新的安全系统。

RC4 的状态不是线性寄存器，而是 256 字节排列及两个索引；这种设计提高了复杂度，却没有消除输出偏差。攻击者可以利用大量密文统计出密钥或明文信息，不能因为初始化和输出过程看起来复杂就认为它满足 PRG 或 CPA 安全。

### 3. RC4 初始化算法

状态是 $S[0],\ldots,S[255]$ 的排列，并维护索引 $i,j$。以下采用 16 字节密钥版本：

```text
for i = 0,...,255:
    S[i] = i
    T[i] = k[i mod 16]
j = 0
for i = 0,...,255:
    j = j + S[i] + T[i] (mod 256)
    swap(S[i], S[j])
i = 0; j = 0
return (S, i, j)
```

### 4. RC4 输出算法

每次调用 `GetBits`：

```text
i = i + 1 (mod 256)
j = j + S[i] (mod 256)
swap(S[i], S[j])
t = S[i] + S[j] (mod 256)
y = S[t]
return (S, i, j), y
```

它通过不断交换排列元素产生输出字节，但“看起来随机”并不等于满足现代安全定义。

### 5. RC4 与 WEP 的失败

WEP 使用 RC4 保护机密性，并使用 CRC-32 做完整性校验。标准 64 位 WEP 实际包含：

- 40 位长期密钥；
- 24 位 IV；
- 每个数据包用不同 IV 生成密钥流。

IV 总数只有 $2^{24}$。按高流量接入点估算，发送约 1500 字节、速率 11 Mbps 的数据时，IV 约数小时就会耗尽并重复。重复 IV 意味着同一长期密钥下重复使用相同或相关的 RC4 密钥流；结合 RC4 的偏差，WEP 可以在很短时间内被破解。WEP 的 CRC-32 也不是密码学消息认证码，攻击者可以构造可接受的修改。WPA-TKIP 虽改善了 WEP 的部分问题，RC4 的弱点仍使其不再推荐。现代 Wi-Fi 应使用 WPA2 或 WPA3，其核心加密通常基于 AES。

## 五、流密码的使用建议

1. 停止使用已知不安全的流密码，例如 RC4。
2. 采用经过公开分析和标准化的方案，例如 ZUC-128/256、Enocoro、Trivium、Grain128-AEAD 等。
3. 私钥加密中，若没有特殊约束，通常优先使用成熟的分组密码及其安全工作模式。
4. 流密码只解决机密性；实际通信还要使用认证加密或独立的消息认证机制。
5. 每次使用都要保证 nonce/IV 不重复，并避免手工设计密钥流生成器。

## 六、全章总结

1. 流密码用短种子确定性地产生密钥流，常通过 XOR 加密消息。
2. 密钥流复用会暴露明文之间的 XOR；密文还可能受到位翻转攻击。
3. LFSR 具有高效和良好周期，但线性结构使其可被约 $2n$ 个输出重建。
4. 非线性可以阻止简单重建，但具体方案仍需严格密码分析。
5. RC4/WEP 的历史说明：高效、广泛部署和“看起来随机”都不能替代安全证明。
