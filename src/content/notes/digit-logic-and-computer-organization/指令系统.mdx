# 指令系统

## 指令系统概述

[TOC]

**指令集体系结构（Instruction Set Architecture）**是一台计算机的抽象模型，是计算机功能的“功能规范说明书”，通常将指令集体系结构简称为**指令系统**。

> [!NOTE]
>
> **ISA** 位于软件与硬件之间的交界面。在硬件部分分为三部分：
>
> - 是否提供“乘法指令”：ISA
> - 如何实现乘法指令（用快速乘法器还是用加法器+移位器实现）、如何实现CPU（单周期？流水线？etc.）：Organization
> - 如何布线、用什么材料等：Implementation

指令集体系结构（ISA）核心部分是指令系统，还包含数据类型和数据格式定义、寄存器设计、I/O空间的编址和数据传输方式等等。

> [!TIP]
>
> **回顾**： **指令执行周期**

### 指令设计

一条指令必须明显或隐含包含以下信息：

- **操作码**：指定操作类型（对何种类型数据做何种操作）
  - 操作码长度：固定 / 可变
- **源操作数或其地址**：一个或多个源操作数所在的地址
  - 操作数来源：主(虚)存 / 寄存器 / I/O 端口 / 指令本身
- **结果值参照**：产生的结果存放何处（目的操作数）
  - 结果地址：主(虚)存 / 寄存器 / I/O 端口
- **下一条指令地址**：下条指令存放何处
  - 下条指令地址 ：主(虚)存
  - 正常情况隐含在 PC 中，改变顺序时由指令给出

> [!NOTE]
>
> 一般而言，我们将以上所谓指令的二进制表示称为**指令字**。其中包括
>
> - **操作码字段（Opcode Field）**：决定这条指令要执行什么操作（如加法、跳转）。
> - **地址码字段 / 操作数字段（Operand Field）**：决定操作数在哪里、或者立即数的值是多少。

### 指令格式的设计

指令格式的选择应遵循的几条基本原则：

- 应尽量短
- 要有足够的操作码位数
- 合理地选择地址字段的个数
- 指令编码必须有唯一的解释，否则是不合法的指令
- 指令字长应是字节的整数倍
- 指令尽量规整

### 指令中的地址码

按照指令中的地址码段数，可以将指令分为以下几类：

- 零地址指令：
  - 无需操作数，如：空操作／停机等
  - 所需操作数为默认的，如：堆栈／累加器等
  - 形式：`OP`
- 一地址指令：其地址既是操作数的地址，也是结果的地址
  - 单目运算，如：取反／取负等
  - 双目运算，另一操作数为默认的，如：累加器等
  - 形式：`OP A1`
- 二地址指令（最常用）：分别存放双目运算中两个操作数，并将其中一个地址作为结果的地址。
  -  形式：`OP A1 A2`
- 三地址指令（RISC 风格）分别作为双目运算中两个源操作数的地址和一个结果的地址。
  - 形式：`OP A1 A2 A3`
- 多地址指令：用于成批数据处理的指令，如:向量 / 矩阵等运算的 SIMD 指令。

## 指令系统设计

设计一个指令系统时，需要考虑以下一些基本问题：

1. **如何设定操作码的位数、编码和操作类型？**
2. **运算指令能对哪几种数据类型进行操作？**
3. **采用什么样的指令格式？**
4. **如何规定通用寄存器的个数、功能、长度等？**
5. **如何设计寻址方式的种类和编码，各种寻址方式下如何计算有效地址？**
6. **如何确定下条指令的地址？**

当然，指令系统设计所涉及的远远不限于上述所列问题，其他方面还包括**标志信息的生成和使用**、**异常和中断处理机制**、**是否采用延迟分支技术**等。 在具体设计过程中，还需要考虑很多细节问题。

### 操作数

**操作数**是指令处理的对象。

基本类型如下：

- 地址（指针）：被看成无符号整数，寄存器编号，也可参加运算以确定主(虚)存地址。
- 数值数据
  - 定点数（整数）：一般用二进制补码表示。
  - 浮点数：大多采用 IEEE754 标准。
  - 十进制数：使用 NBCD 码表示，压缩 / 非压缩（汇编程序设计时用）
- 位、位串、字符和字符串：用来表示文本、声音和图像等
- 逻辑（布尔）数据：按位操作

> [!NOTE]
>
> **关于位、位串**：
>
> 4 bits is a nibble（一个十六进制数字）
>
> 8 bits is a byte
>
> 16 bits is a half-word 
>
> 32 bits is a word

> [!TIP]
>
> **操作数存放在什么位置**？
>
> CPU 中的**寄存器**或**内存单元**中，也可以以**立即数（`imm`）**的方式直接出现在指令中。

关于操作数的两个例子如下：

**IA-32**: 

- 基本类型：
  - 字节、字(16 位)、双字(32 位)、四字(64 位) 
- 整数：
  -  16 位、32 位、64 位三种 2-补码表示的整数
  -  18 位压缩 8421 BCD 码表示的十进制整数
- 无符号整数（8、16或32位）
- 近指针：32位段内偏移（有效地址）
- 浮点数：IEEE 754（80位扩展精度浮点数寄存器）

**RISC-V**:

- 基本类型：字节、半字(16 位)、字(32 位)、双字(64 位) 
- 整数： 16 位、32 位、64 位三种 2-补码表示的整数
- 无符号整数：（16、32 位）
- 浮点数：IEEE 754（32 位 / 64 位浮点数寄存器）

### 寻址方式

**寻址方式**是指令或操作数地址的指定方式。即根据地址找到**指令**或**操作数**的方法。通常情况下，寻址方式指“**操作数的寻址方式**”，即指令给出操作数或操作数地址的方式。

>  [!TIP]
>
> 地址码编码由操作数的寻址方式决定。

指令的寻址较为简单：

- 正常：PC 增值
- 跳转 ( jump / branch / call / return )：同操作数的寻址

操作数的寻址则更加复杂，因为其来源与结构都十分多变：

- 操作数来源：寄存器 / 外设端口 / 主(虚)存 / 栈顶
-  操作数结构：位 / 字节 / 半字 / 字 / 双字 / 一维表 / 二维表 /… 

通常把指令中给出的操作数所在存储单元的地址称为**有效地址**。可通过指令的**寻址方式**和**地址码**算出有效地址。

假设 $A=$ 地址字段值，$R=$ 寄存器编号， $EA=$ 有效地址， $(X)=X$ 中的内容。指令为 `OP R A ...`，则基本寻址方式及其优缺点见下表：

| **方式**       | **算法**         | **主要优点**       | **主要缺点**   | **操作数位置**   |
| -------------- | ---------------- | ------------------ | -------------- | ---------------- |
| **立即数**     | 操作数 = A       | 指令执行速度快     | 操作数幅值有限 | 指令（寄存器）中 |
| **直接**       | $$EA = A$$       | 有效地址计算简单   | 地址范围有限   | 内存中           |
| **间接**       | $$EA = (A)$$     | 有效地址范围大     | 多次存储器访问 | 内存中           |
| **寄存器直接** | 操作数 = (R)     | 指令执行快，指令短 | 地址范围有限   | 寄存器中         |
| **寄存器间接** | $$EA = (R)$$     | 地址范围大         | 额外存储器访问 | 内存中           |
| **偏移**       | $$EA = A + (R)$$ | 灵活               | 复杂           | 内存中           |
| **栈**         | EA = 栈顶        | 指令短             | 应用有限       | 内存中           |

指令中的地址码字段称为**形式地址**。实际上，偏移寻址分以下三种：

- 变址寻址：偏移量存在**变址寄存器** $I$，形式地址是基准地址 $A$，有效地址为 $EA=A+(I)$
  - 可为循环重复操作提供一种高效机制，如实现对线性表的方便操作

- 相对寻址：基准地址隐含由 $PC$ 给出，地址码字段 $A$ 给出偏移量，有效地址为 $EA=(PC)+A$
  - 可用来实现程序(公共子程序)的浮动 或 指定转移目标地址

- 基准寻址：基准地址存在**基址寄存器** $B$，偏移量 $A$，有效地址为 $EA=(B)+A$
  - 可用来实现多道程序重定位 或 过程调用中参数的访问


> [!TIP]
>
> 是否有专用的变址寄存器、基址寄存器由处理器决定。现代 CPU 设计如 RISC-V，

> [!TIP]
>
> 在偏移寻址 $EA=A+(R)$ 中，
>
> - $R$ 可以显式地给出，也可以隐含地给出。
> - $R$ 可以为 PC、基址寄存器、变址寄存器。

### 操作类型和操作码编码

#### 指令格式（Instruction Format）

指令的操作类型由操作码字段指定，而操作码有以下两种编码方式：

- Fixed Length Opcodes (定长操作码)
  - 定长指令字和定长操作码便于快速访问和译码；
  - 基本思想：指令的操作码部分采用固定长度的编码，假设操作码固定为6位，则系统最多可表示64种指令
  - 译码方便，但有信息冗余：IBM360/370 采用 8 位定长操作码，最多可有 256 条指令只提供了 183 条指令，有 73 种编码为冗余信息

- Expanding Opcodes (扩展操作码)
  - 变长指令字和变长操作码使机器代码更紧凑。
  - 基本思想：将操作码的编码长度分成几种固定长的格式。

扩展编码的基本思想就是操作码按短到长进行扩展编码。对于一般最多二地址指令的机器而言，二地址指令操作码最短，零地址指令的操作码最长，所以，按照**二地址 $\rightarrow$ 单地址 $\rightarrow$ 零地址**的顺序进行编码。

> [!TIP]
>
> 定长操作码，也可以是变长指令字；但变长操作码，一般不会是定长指令字。

通常，指令系统操作类型按功能分为以下几种：

- 算术和逻辑指令
- 移位指令
- 数据传输指令
- 串指令
- 顺序控制指令
- 系统控制指令
- 输入 / 输出指令

### 标志信息的生成与使用

**标志信息**也称为**条件码（Condition Codes, CC）**或**状态位（status）**，生成的标志位信息可由专门的条件码寄存器来存放，也可以由通用寄存器存放。

> [!NOTE]
>
> 条件转移指令（分支指令）通常根据程序当前生成的标志信息进行转移。
>
> 执行算术指令或显式比较指令来设置 CC。

常用的标志由四种：

- SF: Signal Flag
- OF: Overflow Flag
- CF: Carry Flag
- ZF: Zero Flag

## 指令系统实例：RISC-V



> [!NOTE]
>
> 关于 RISC 风格指令集的三大架构：
>
> - MIPS: 1981 年开始；扩展性较弱，主要面向高性能服务器/工作站场景；原公司于 2023 年宣布放弃自研的 MIPS 架构，‌据称是因市场和商业等诸多因素，选择加入 RISC-V 阵营，继续基于 RISC-V 开发处理器内核。
> - ARM: 1983 年开始；低功耗、高性价比，广泛应用于移动设备（手机）、嵌入式系统等；目前占据全球 32 位嵌入式处理器市场 75% 份额
> - RISC-V: 2010年开始，伯克利分校此前已开发了四代 RISC 指令集；2025 年，RISC-V 芯片的全球市场占比首次突破 25%，在嵌入式、物联网等领域快速增长，但服务器和 PC 上仍以 X86 等芯片为主导。

### 指令格式

采用 32 位**定长指令字**格式，共有6种指令格式

- R-型为寄存器操作数指令
- I-型为短立即数或装入（Load）指令
- S-型为存储（Store）指令
- B-型为条件跳转指令
- U-型为长立即数操作指令
- J-型为无条件跳转指令



### RISC-V基础整数指令集

这里采用**寄存器传送级（Register Transfer Level, RTL）**语言来描述指令功能。约定如下：

- R[r] 表示通用寄存器 r 的内容
- M[addr] 表示存储单元 addr 的内容
- PC 表示 PC 的内容
- M[PC] 表示 PC 所指的存储单元的内容
- SEXT[imm] 表示对 imm 进行符号扩展
- ZEXT[imm]：对 imm 进行零扩展
